# 單人驗收測試計畫（G-04）

## 目的與原則

目前系統由單一測試者驗收。本階段先確認核心帳務流程在單一家庭、單一登入者情境下正確，再安排第二位家庭成員及跨成員權限測試。

- 測試資料與真實家庭帳務分開：請先建立一個名稱明確的「驗收測試家庭」，使用專用測試帳戶、測試帳戶餘額及虛構交易。
- 不要把測試交易輸入真實家庭；不要上傳含個資、完整銀行帳號或真實發票的影像。
- 不要在正式資料庫直接執行 SQL 清除測試資料。測試資料清理應使用系統提供的正常作廢／刪除流程，且先確認影響範圍。
- 本計畫不要求新增雲端 OCR、簡訊、郵件或其他可能產生費用的服務。
- 測試過程記錄：日期、裝置／瀏覽器、操作步驟、預期結果、實際結果、截圖或錯誤訊息。

## 測試順序與驗收條件

### A. 登入與家庭空間

- [ ] Email／密碼登入成功，重新整理後登入狀態合理維持。
- [ ] 登出後受保護頁面不能繼續讀取私人資料。
- [ ] 可切換至驗收測試家庭，頁面標題與家庭資料一致。
- [ ] 無權限功能不顯示或無法操作；直接呼叫 API 也應被拒絕。
- [ ] 手機直向、橫向及桌面瀏覽器版面均可操作。

### B. 帳戶與基本交易

建立測試用現金帳戶及銀行帳戶，各設定一筆容易辨識的期初餘額。

- [ ] 新增收入、支出，列表、帳戶餘額及報表同步更新。
- [ ] 修改交易後，原帳戶及新帳戶餘額正確。
- [ ] 作廢交易後，餘額回復正確，且不留下重複計算。
- [ ] 同一筆交易連續送出或重新整理，不會產生重複資料。
- [ ] 轉帳兩端金額相等；手續費獨立列為支出；轉帳本金不被報表重複計入。
- [ ] 信用卡消費、繳款及退款不會重複計入家庭收入／支出。

### C. 帳單與付款

- [ ] 建立不同幣別帳單，未付款、部分付款、全額付款狀態正確。
- [ ] 同幣別付款匯率固定為 1，帳單金額與扣款金額一致。
- [ ] 跨幣別付款輸入匯率後，實際扣款金額按四位小數及四捨五入規則計算。
- [ ] 部分付款多次累計後，已付、未付餘額正確。
- [ ] 部分退款及多次退款均能追溯各次匯率、實際退回金額及匯兌差額。
- [ ] 退款不能錯誤退回到與原付款不同的帳戶幣別。
- [ ] 作廢／修改付款後，帳戶交易、帳單餘額及報表一致。

### D. 定期帳單

- [ ] 建立每月定期帳單，確認下一期日期與金額。
- [ ] 同一期間重複執行產生流程，不會重複建立帳單。
- [ ] 暫停、恢復及結束定期帳單後，後續期數符合設定。

### E. 銀行匯入與對帳

請使用自行製作、無真實帳號的測試 CSV；先保留一份原始檔。

- [ ] 匯入前可預覽欄位與資料筆數。
- [ ] 日期、金額、摘要、收支方向及幣別解析正確。
- [ ] 相同檔案重複匯入時能提示重複資料，不會無聲新增重複交易。
- [ ] 對帳工作區可建立對帳批次並顯示未配對項目。
- [ ] 一對一、多筆合併及人工配對後，差額與狀態正確。
- [ ] 排除項目、差異原因及重新開啟對帳的歷程可追溯。
- [ ] 完成對帳後的摘要、差異清單及報表數字一致。

### F. 收據辨識（本機試用）

- [ ] 使用不含個資的測試收據影像進行辨識。
- [ ] 可選擇收據類型並檢視、修改辨識欄位。
- [ ] 更換影像或收據類型時，不會沿用上一張的錯誤辨識結果。
- [ ] 辨識結果只帶入待確認表單，不會未經確認自動建立支出。
- [ ] 首次載入 OCR 語言資源時，了解其會下載模型資料；此功能不呼叫雲端 OCR API，但不是完全零網路流量。

### G. 報表與匯出

- [ ] 日、月、年報表的收入、支出、結餘與明細可互相核對。
- [ ] 月報每日明細日期使用 YYYY-MM-DD，且跨午夜／時區不偏移。
- [ ] 多幣別分開呈現，不將不同幣別直接加總。
- [ ] CSV 可正常以繁體中文開啟，日期、欄位及總計正確。
- [ ] 匯出內容與畫面篩選條件一致；載入失敗時不會匯出舊資料。

### H. 稽核與資料安全

- [ ] 新增、修改、作廢等重要操作保留操作者及時間。
- [ ] 權限不足時，前端與 API 都拒絕操作。
- [ ] 家庭切換、登出後，不會看到前一家庭殘留資料。
- [ ] 備份工作流程成功，並確認備份產物及完整性資訊存在。
- [ ] 不在測試紀錄、截圖或匯出檔中暴露密碼、Token、完整帳號或個資。

## 缺陷回報格式

每個問題請提供：

1. 測試項目（例如 E-03）。
2. 使用裝置／瀏覽器與發生時間。
3. 操作前置條件及逐步操作。
4. 預期結果與實際結果。
5. 錯誤畫面截圖、網址及可重現的測試資料（遮蔽個資）。

## 單人驗收完成標準

- 所有核心帳務、付款、對帳及報表項目通過。
- 不存在會造成餘額錯誤、重複入帳、跨家庭資料洩漏或未授權操作的重大缺陷。
- 所有未通過項目都有缺陷紀錄及處理狀態。
- 完成上述項目後，再進入第二位家庭成員邀請、角色權限、資料範圍及多人同時操作測試。
