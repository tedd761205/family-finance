# 電子發票 CSV 匯入、保存與家庭歷史搜尋

## 目的與資料流程

電子發票工作區支援使用者匯出的 M/D pipe-delimited CSV。匯入流程分為兩段：

1. **本機解析預覽**：瀏覽器讀取 CSV，配對發票表頭與商品／折扣明細，執行金額核對。
2. **人工確認保存**：使用者按下「儲存發票紀錄」並確認後，系統才將整理後的發票表頭與明細寫入目前家庭的資料庫。

原始 CSV 不會上傳或保存。載具號碼不會保存；只保留載具類型名稱作為來源資訊。保存發票不會自動建立收入、支出、帳單或付款紀錄。

## 支援格式

- 表頭列：`M|載具名稱|載具號碼|發票日期|商店統編|商店店名|發票號碼|總金額|發票狀態`
- 明細列：`D|發票號碼|小計|品項名稱`
- 可選擇包含 `表頭=`、`明細=` 前綴的欄位說明列。
- 資料列以 `M|` 或 `D|` 開頭，欄位分隔符號為直線 `|`。
- 支援 UTF-8、Big5／CP950（瀏覽器 TextDecoder 的 big5 編碼名稱）與 UTF-8 BOM。
- 日期採西元 `YYYYMMDD`。
- 金額支援整數及最多兩位小數；D 明細可為負數或零。

## 解析與核對規則

1. 依發票號碼將 M 表頭與 D 明細配對。
2. 保留每一筆原始明細，不合併相同商品。
3. 負數明細視為折扣／折讓等調整項，不可刪除或轉成正數。
4. 每張發票計算 D 明細加總，與 M 表頭總金額比較。
5. 無明細、明細加總不一致、重複表頭、找不到表頭的明細及格式錯誤均列為檢查警示。
6. 載具號碼在預覽畫面不顯示，也不會保存到資料庫。

## 正式保存與重複檢查

- 保存前會顯示確認訊息，並說明這項操作只保存發票資料，不會建立正式帳務。
- 系統保存匯入批次、發票表頭及商品／折扣明細，並記錄執行者與時間。
- 每個家庭的未作廢發票以「發票號碼」維持唯一。已存在的有效發票或同批重複發票會略過，不會覆寫舊資料；作廢後可以重新匯入修正版，舊版本仍保留在作廢歷史中。
- 已保存資料採軟刪除／作廢，不直接刪除；作廢原因、操作者及時間會留下稽核紀錄。
- 發票記錄及明細使用家庭 ID 關聯，避免跨家庭資料引用。
- 家庭資料範圍遵循角色設定：管理員、財務管理員、記帳人員及檢視人員可依角色查看家庭範圍；一般成員依自己的資料範圍查看，且只能作廢自己建立的發票。
- CSV 預覽會綁定解析時選取的家庭；切換家庭後，必須重新選取檔案才能保存，避免把發票誤存到其他家庭。歷史搜尋請求亦會在切換家庭時作廢舊回應。
- 目前保存的幣別為 TWD；如日後支援跨國發票，再另行設計幣別來源及稅額欄位。

## 家庭歷史發票搜尋

歷史發票區跨所有已保存匯入批次查詢，不需要重新選取原始 CSV。支援：

- 發票號碼、店家名稱、商品／折扣名稱、統一編號、發票日期、發票狀態及金額關鍵字。
- 日期起迄範圍。
- 明細核對一致、金額不一致、缺少商品明細、來源檔重複等狀態。
- 顯示已作廢的歷史紀錄。
- 分頁瀏覽、展開商品與折扣明細。
- 顯示匯入批次、明細筆數、核對結果及（如有）連結的交易編號。

## 安全及帳務原則

- 所有保存與搜尋 API 都要求登入、家庭成員資格及對應的 `invoices.view`／`invoices.import`／`invoices.void` 權限。
- 歷史搜尋套用家庭及 own／family 資料範圍，不允許藉由更換 family_id 讀取其他家庭資料。
- 不保存載具號碼、載具密碼、原始 CSV 或任何認證秘密。
- 電子發票不等於一筆銀行扣款；保存發票不會自動建立交易，也不會假設發票總額就是實際付款額。
- 未來要將發票轉為支出時，必須先選擇帳戶／付款方式、分類與日期，檢查是否已有相關支出，再由使用者明確確認；不可直接把匯入資料自動入帳。
- 財政部載具 API 尚未接通；CSV 匯入保存不代表已完成官方載具同步。

## 限制

- 單檔 10 MB、最多 20,000 行；單次保存最多 1,000 張發票、每張最多 1,000 筆明細，單批商品／折扣明細合計最多 20,000 筆。超過上限會在送出前提示分批匯入。
- 預覽只在目前頁面記憶體中；刷新頁面後需重新選檔。已保存的歷史紀錄不受清除預覽影響。
- 發票來源 CSV 不會保留；日後如需稽核原始檔，需另外設計私有附件保存、存取權限及保存期限。
- 官方財政部載具 API 需完成申請與核准程序，目前尚未實作。
