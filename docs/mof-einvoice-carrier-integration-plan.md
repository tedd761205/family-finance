# 財政部電子發票載具串接評估與實作規劃

> 文件狀態：規劃／授權資格待確認  
> 查核日期：2026-11-27  
> 本文件不代表已取得財政部 API 授權，也不代表系統已連線。

## 1. 結論與實作原則

家庭記帳系統的電子發票功能分成兩種不同能力：

1. **本機掃描／辨識**：使用者以手機掃描紙本電子發票雙 QR Code，或拍攝一般收據，再由前端解析與 OCR 擷取候選資料。
2. **官方載具同步**：透過財政部電子發票整合服務平台 API，依使用者授權查詢雲端發票表頭與明細。

目前系統已有第 1 類能力；第 2 類尚未實作。不得把 QR Code 解析、OCR、或輸入手機條碼顯示成「已連結財政部載具」。

在取得 API 使用資格與核准 AppID／APIKey 前，不呼叫正式 API、不要求家庭成員提交載具驗證碼、不使用非官方登入模擬、網頁爬取或未經核准的第三方端點。

## 2. 財政部規範與申請門檻

依現行《電子發票應用程式介面使用規範》：

- 規範所稱開發者為營業人、組織團體或政府機關（構）。
- 須依財政資訊中心提供的申請方式提出申請，審核通過後才核發 AppID 與 APIKey。
- 授權期間最長三年，期滿須依規定重行審核。
- 資訊安全制度須符合 CNS 27001 或 ISO 27001，範圍須涵蓋使用 API 的軟體產品及相關資訊業務活動。
- 必須取得產品使用者同意，提供停止使用、停止利用及刪除資料的權利；同意紀錄須每半年重新取得並留存。
- 若將查得的發票資料、使用紀錄等用於原本電子發票查詢服務以外的目的，須清楚告知目的、範圍、類別、期間、地區、對象、方式及個資權利，並取得重新同意；相關儲存及使用軌跡至少留存六個月。
- 軟體若提供使用者查詢電子發票資料，規範要求一併提供雲端發票捐贈功能。

**目前的主要阻礙**：本專案是由個人維護、供家庭使用的系統。規範的開發者定義與資安要求，使我們不能先假設個人自用專案一定符合資格。必須先向財政資訊中心確認自然人自用家庭系統是否可申請、可接受的申請主體及資安證明方式。

## 3. 官方 API 能力（待核對申請後適用的最新規格）

官方公開文件列有下列相關能力：

- 載具發票表頭查詢：查詢載具內的雲端發票清單。
- 載具發票明細查詢：依發票號碼與日期查詢消費明細。
- 手機條碼歸戶載具查詢：查詢已歸戶的載具資訊。
- 載具發票捐贈：支援規範要求提供的捐贈服務。

相關載具查詢會使用核准的 AppID，以及使用者載具資訊和驗證資訊。正式開發時，必須以財政資訊中心核發的最新規格、測試環境和申請核准範圍為準；不可直接複製舊版 PDF 範例當成正式 API 合約。

官方於 2025-04-23 修訂的流量管制作業注意事項，對單一 AppID 設有總請求上限，並對相同參數的發票表頭、明細及載具查詢設定更嚴格的重複查詢頻率限制。同步工作必須具備快取、去重、退避重試與請求紀錄，不可讓使用者連按造成大量查詢。

## 4. 專案現況盤點（2026-11-27）

### 已有

- `static/local-receipt-parser.js`：解析紙本電子發票左、右 QR Code，擷取發票號碼、日期、金額、賣方／買方統編及品項候選資料。
- `static/local-receipt-ocr.js`：本機收據掃描／辨識流程。
- `app/routers/ocr_task.py`：帳單圖片 OCR 任務 API。
- 家庭交易、附件、權限及稽核紀錄等既有基礎。

### 尚未建立

- 財政部載具連線／同步 Router。
- 載具連線資料 Model。
- AppID/APIKey 的正式設定與秘密管理。
- 使用者載具驗證資料的安全保管流程。
- 官方 API 同意書、半年重新同意與撤回流程。
- 官方發票匯入暫存、去重、明細比對及捐贈流程。

因此目前不得宣稱載具自動同步已完成。

## 5. 建議實作架構

### 5.1 每位家庭成員各自授權

- 每位成員自行連結自己的手機條碼／載具。
- 系統只允許本人新增、重新驗證、解除連結。
- 不共用家庭管理者的載具密碼，也不將家庭成員的驗證資料互相顯示。
- 使用者可查看資料同步來源與最近同步時間。

### 5.2 憑證與秘密管理

- AppID/APIKey 僅放在後端秘密設定，不傳到瀏覽器、不寫入程式碼、不回傳前端。
- 載具驗證資訊屬高度敏感憑證；未完成資安設計前不得收集。
- 若正式流程需要保存以供定期同步，必須採用伺服器端加密保存、金鑰與資料分離、權限控管、存取稽核、遮罩日誌及解除連結即刪除等措施。
- API 回應、載具驗證碼、APIKey 不得寫入一般應用程式日誌。

### 5.3 同意與資料用途分層

同意畫面至少分成不同用途，不以一次勾選概括全部權限：

1. 財政部電子發票查詢服務授權。
2. 將查得發票資料存入家庭記帳系統作為家庭記帳、分類與對帳用途的額外同意。
3. 是否同意將發票資料分享給指定家庭成員／家庭空間。
4. 雲端發票捐贈時，針對選定發票再次確認。

必須可檢視同意版本、同意時間、撤回時間、重新同意日期與操作人。每半年重新取得同意；撤回或刪除時，依使用者選擇及法規要求停止同步、刪除連線憑證與相關資料，並留下必要的稽核紀錄。

### 5.4 匯入與入帳分離

官方同步完成後，發票先進入「待確認發票」，不直接產生正式支出：

- 保存來源、發票號碼、日期、賣方、總額、品項與查詢時間。
- 依發票識別資訊去重，避免同一發票由不同歸戶載具重複匯入。
- 可建議支出類別，但不自動決定分攤人、付款帳戶或正式入帳。
- 使用者確認後，才建立正式交易；原始發票資料與正式交易保持可追溯關係。
- 如發票已由紙本 QR／收據 OCR 建立候選資料，應先提示可能重複並提供比對畫面。

### 5.5 使用者介面狀態

在尚未取得核准前，介面只能顯示：

- 「財政部載具同步：尚未啟用」
- 「目前可使用：紙本電子發票雙 QR 掃描、收據拍照辨識」
- 「官方同步需完成申請與審核」

日後取得正式授權後，再依實際狀態顯示「尚未連結」、「已連結」、「需要重新驗證」、「同意即將到期」、「同步失敗」等狀態。不得顯示虛假的「已連結」。

## 6. 開發階段與驗收標準

| 階段 | 工作 | 通過條件 |
|---|---|---|
| 0. 資格確認 | 向財政資訊中心確認自然人自用專案資格、申請主體及資安證明 | 取得明確答覆及可行申請路徑 |
| 1. 授權準備 | 依核准要求準備申請、隱私告知、同意及資安流程 | 取得核准 AppID/APIKey，且秘密設定完成 |
| 2. 後端串接 | 建立載具連線、API client、查詢、限流、重試及稽核 | 官方測試環境查詢成功，憑證不外洩 |
| 3. 家庭流程 | 每位成員自行授權、解除連結、撤回及半年重新同意 | 權限隔離、撤回與刪除測試通過 |
| 4. 發票工作區 | 匯入清單、明細、去重、待確認及捐贈 | 重複發票不重複入帳，未確認不寫入正式交易 |
| 5. 正式驗收 | 以核准環境測試多載具、跨月份、逾時及 API 限流 | 不遺失資料、不重複入帳、錯誤可恢復 |

## 7. 目前應先詢問財政部的事項

財政部電子發票整合服務平台公開客服：0800-521-988。建議聯繫時一次確認：

1. 個人自行開發、僅供自己家庭使用、不對外營利或公開提供的記帳系統，是否符合 API 開發者申請資格？
2. 若自然人不符合，是否有可供家庭自用的正式授權途徑或其他合法方案？
3. CNS 27001／ISO 27001 要求是否必須提出有效證書，或可用其他制度文件與查核方式證明符合？
4. 家庭成員自行授權載具後，若將發票明細另行儲存作家庭記帳及家庭共享用途，應如何設計重新同意與資料保存告知？
5. 本專案若只查詢發票、不代為捐贈，是否仍必須提供雲端發票捐贈功能，以及捐贈 API 的申請範圍？

在取得回覆前，不建議輸入家人的手機條碼驗證碼或開發正式同步請求。
